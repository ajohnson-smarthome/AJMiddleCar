# J1 — Первый запуск с нуля

Задача 2.1 (`AJM-76`). Снимок кода на 2026-09-19, после `ajm-64-known-fixes` 2.1 (`AJM-67`,
обязательный мастер по первому кадру) и 2.2 (`AJM-68`, выпуск только с образами обеих плат) —
там, где спека `openspec/specs/` ещё описывает старое поведение, ожидание берётся из дельты
`openspec/changes/ajm-64-known-fixes/specs/`.

Порядок правды по `design.md`: (a) `docs/protocol.md` и контракты, (b) design-документы
`docs/superpowers/specs/`, (c) `README.md`/`CLAUDE.md`, (d) здравый смысл водителя. Вердикты:
`✓` — код делает то, что ждёт спека или замысел; `✗` — расходится, есть issue; `?` — не решить
без стенда, строка в `## Стенд`.

## Маршрут

1. Адаптер в телефон: NCM-интерфейс, `192.168.7.1`, DHCP хосту, `usb.state`.
2. Запуск приложения: лестница `[адаптер, машинка]`, стадия адаптера — `/version` по USB, пять исходов чтения.
3. Адаптер ответил → «проверяю» → выпуск: тег с номером сборки и образы обеих плат, иначе удержание.
4. Правило адаптера: личность → откат → выпуск («не тот адаптер», «откат», «обновление»).
5. Принудительное обновление адаптера: проверка → скачивание → заливка → перезагрузка → «Готово» / «Прошито» / отказ → стадия заново.
6. Стадия машинки, «добраться»: `/status` адаптера → `POST /wifi` → `searching` / `joining` / `connected` / `failed`, один запрос на вход.
7. Машинка достигнута: `/version` через реле; тишина — «ищу машинку»; правило машинки («другая машинка», откат, обновление).
8. Принудительное обновление машинки: образ через реле, перезагрузка машинки под живой ассоциацией адаптера, окно 60 с.
9. Первая загрузка нового образа машинки: точка доступа → камера → подтверждение образа → ворота радио → прошивка радио и перезагрузка → вторая загрузка.
10. Лестница пройдена → сессия: `hello` → `live` → сверка `fw` → экран вождения.
11. Некалиброванная машинка: первый кадр `motors.calibrated:false` → обязательный мастер из трёх экранов → импульсы → таблица → закрытие.
12. Первая езда: команда → моторы по таблице (или по умолчанию).
13. Отдельно: запрет локальной сети.
14. Отдельно: выпуск без образа одной из плат.
15. Отдельно: `motors.bus: down` на первом включении.

### 8. Принудительное обновление машинки

- **Ожидание.** `app/firmware-update` → «Заливка — один запрос», «Перезагрузка — ждём другую версию»: окно машинки 60 с — «ей поднимать радио и камеру, а адаптеру — заново присоединяться к её сети»; истёкшее окно — «Прошито», не отказ. `car/ota-and-rollback`: ответ `ok` до перезагрузки; `car/radio-and-network` → «softAP»: перезагрузка машинки — перезагрузка точки, «станция, всё ещё считающая себя присоединённой, шлёт в пустоту, пока не переприсоединится сама (наблюдено 2026-09-14; ответственность — `dongle/car-join`)». `dongle/car-join` → «Uplink»: каждая датаграмма или **неотвеченная попытка соединения** к машинке удлиняет серию; порог → переприсоединение, не чаще раза в интервал. `docs/bringup.md:318-340` — тот самый случай и починка: «двадцать страйков … не чаще одного раза в десять секунд».
- **Код.** Пульт: `FirmwareFlow.forCar` (`FirmwareFlow.swift:247-255`) — `/version` через реле с тайм-аутом **2 с**; окно `rebootWindow(.car) = 60` (`UpdateRules.swift:184-189`); сторож перезагрузки — `sleep 500 мс` + `refresh()` в цикле (`FirmwareFlow.swift:208-225`), то есть один опрос каждые ~2,5 с, пока машинка молчит; тайм-аут закрывает соединение к адаптеру (`CarTransport.swift:567-570, 649-653`). В этот момент сессии нет (`Phase.opensLink`, `AppFlow.swift:33-38`), реле реального времени молчит.

- `--device`, `--no-version`, `--rollback` — «другая машинка», день-флаг и откат на гейте воспроизводимы; «откат» у мока не переживает «перезагрузку» так, как у загрузчика (`rolled_back` сбрасывается следующим принятым `/ota`) — что и нужно шагу 4.

## Швы

Пары capability, пройденные этим путешествием (для карты покрытия 3.2):

- `app/launch-ladder` ↔ `dongle/usb-network` (присутствие адаптера, запрет локальной сети)
- `app/launch-ladder` ↔ `dongle/api` (`/version`, `/status`, `POST /wifi`, конверт)
- `app/launch-ladder` ↔ `dongle/car-join` (бюджет присоединения, слова состояния, `failed` и «Повторить», uplink)
- `app/launch-ladder` ↔ `shared/release` (тег с номером, оба образа, удержания)
- `app/launch-ladder` ↔ `app/firmware-update` (парковка, `updateFinished`, «Повторить» — F1)
- `app/launch-ladder` ↔ `car/status-and-version` (`/version`, `rolled_back`, личность)
- `app/launch-ladder` ↔ `app/drive-session` (передача управления, `carIdentified`, стражи)
- `app/firmware-update` ↔ `dongle/api` (`POST /ota` адаптера, окно 30 с)
- `app/firmware-update` ↔ `car/ota-and-rollback` (`POST /ota` машинки, окно 60 с)
- `app/firmware-update` ↔ `dongle/relay` ↔ `dongle/car-join` (опрос `/version` через TCP-реле, страйки uplink — F2, F4)
- `car/ota-and-rollback` ↔ `car/radio-and-network` (подтверждение образа до ворот радио, перезагрузка после)
- `car/radio-and-network` ↔ `dongle/car-join` (перезапуск точки доступа под живой ассоциацией — F2)
- `car/radio-and-network` ↔ `shared/release` (образ радио внутри образа выпуска)
- `app/calibration` ↔ `car/calibration` (первый кадр, импульс, таблица)
- `app/calibration` ↔ `car/status-and-version` ↔ `car/actuator-arbiter` (`motors.bus` и `spin` — F3)
