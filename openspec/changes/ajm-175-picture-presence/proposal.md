# Proposal

## Why

При включении видео плашка «Нет картинки» проходит три шага вместо одного: «Камера ждёт» → «Нет картинки» без причины поверх уже идущей картинки → исчезает до секунды спустя (AJM-175). Причина — по коду: заголовок плашки держится на `hasPicture`, который публикуется только секундным тиком статистики, а строка причины — на телеметрии 5 Гц; первый кадр уходит в слой сразу, но флаг ждёт тика. Гонки памяти нет — есть гонка тактов трёх источников.

## What Changes

- Плашка «Нет картинки» уходит **с первым собранным кадром**, а не с ближайшим секундным тиком: присутствие картинки поднимается из приёмника в момент сборки кадра; секундный тик остаётся только для обратного перехода — «стало несвежим» (две секунды без кадра, как и было).
- Свежесть картинки — чистая, хост-тестируемая арифметика (`PicturePresence`: кадр в момент t → есть; нет кадров две секунды → нет; сброс при открытии сокета), которой пользуется `VideoLink`; порог «две секунды» перестаёт быть числом внутри таймера.
- Кадр от уже закрытого сокета не поднимает флаг: переход через главный актор проверяет, что сокет — текущий (как `socketFailed`).

Провод, машинка, мок — не затрагиваются.

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `app/drive-hud`: «„Нет картинки“ — поверх последнего кадра, езда не прерывается» — плашка исчезает с первым собранным кадром (было «в пределах секунды»); сценарий «Кадры вернулись» уточняется, добавляется «Включение видео с экрана».

## Impact

- `app/AJMiddleCar/VideoLink.swift` — `.frame` в `receiveLoop` поднимает `hasPicture` через главный актор; `publishStats` считает свежесть через `PicturePresence`; `close()` как прежде сбрасывает.
- Новый `app/AJMiddleCar/PicturePresence.swift` + хост-тест `app/tests/picturepresence` (по образцу `videohold`, с файлом `sources`); `tools/test-all.sh` подхватывает его сам.
- `DriveView.noPicture` — без изменений: строка причины по телеметрии остаётся для настоящего простоя (машинка говорит `streaming`, кадров нет).
