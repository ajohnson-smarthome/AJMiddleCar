# J5 — Конфигурация и калибровка

**Главный вопрос:** может ли пульт показывать не то, что держит машинка, и как долго.
**Ответ по трассе:** может — до перезапуска приложения, и никто об этом не скажет
(шаги 8–9, `AJM-99`). Всё остальное на маршруте — от проверки тела до импульса во время
возврата — сходится со спеками; расхождения на краях: шина `down` под мастером (`AJM-100`),
закрытие обязательного мастера (`AJM-102`), загрузка старой записи (`AJM-104`), запись без
действия пользователя (`AJM-106`), два бюджета времени и две лишних записи (`AJM-109`,
`AJM-112`, `AJM-115`).

Capabilities: `car/config`, `car/calibration`, `car/drive`, `car/status-and-version`,
`app/settings`, `app/calibration`, `app/drive-session`. Дельта `ajm-64-known-fixes` для
`app/calibration` (AJM-67, слит) — правда о мастере по требованию; базовая спека там устарела.
Снимок кода — `main` на 2026-09-19 (`8f97d26`).

## Маршрут

1. Чтение: `GET /config` — шесть доменов как их держит машинка; разогрев `wheel`/`chassis`/`video` при открытии сессии.
2. Экран домена: читать прежде, чем показывать; «Не прочитано» / «Прочитать снова».
3. Запись с экрана: домен целиком и только он, только прочитанное и изменённое; ответ машинки — правда.
4. Машинка проверяет всё тело до применения: домены, поля, типы, диапазоны, округление `fixed`.
5. Принято — применено и сохранено до ответа; повтор без записи во флеш; потребители видят сразу.
6. Отказ записи (`500 write_failed`): откат домена на машинке; пульт → «Не прочитано» → «Прочитать снова».
7. Старт машинки: восстановление из NVS, умолчания, запись старше поля, значение вне диапазона.
8. Перезагрузка машинки при живом пульте: сессия заново, кэш пульта живёт дальше.
9. Стирание NVS при смене формата: `storage.reset_at_boot`, `motors.calibrated:false` — что видит пульт.
10. Таблица калибровки: `GET /calibration`, `inverted`, раскладка по умолчанию, `motors.calibrated`.
11. Мастер по требованию: первый кадр `false` (AJM-63 → AJM-67), закрытие по `true` или по сохранению, окно 2 с.
12. Мастер по желанию: из настроек, «назад» в любом состоянии.
13. Шаг мастера: импульс пары → `200` после конца импульса → колесо → направление; несостоявшийся импульс.
14. Импульс во время езды: арбитр, сторожевой таймер, крошки.
15. Импульс во время возврата по крошкам.
16. Импульс при `update`/`safe_stop` (`409`) и при `motors.bus: down`.
17. Сохранение таблицы: вся или ничего; проверка; сохранить → применить → ответ таблицей; отказ → «Повторить».
18. Уход с экрана и обрыв сессии во время импульса и во время сохранения.

## Трасса

### 1. Чтение и разогрев
- **Ожидание.** `car/config` → «Чтение — вся конфигурация»: `GET` — все домены, все поля, действующие значения, под конвертом. `app/settings` → «Кэш доменов»: при открытии сессии заранее читаются `wheel`, `chassis`, `video`. `app/drive-session` → «Режим экрана вождения»: `video` запрашивается при открытии сессии, чтобы первая отрисовка была в нужной раскладке.
- **Код.** `cfg_api.c:119-134` `reply_config` обходит `CFG_DOMAINS`, каждый домен через `binding.get` и `render_domain` (`:100-115`); печать `fixed` со знаками по `scale` — `cfg_value.h:42-58`; буфер 400 байт против ~270 максимальных. Пульт: `CarLink.swift:189-196` на `.sessionOpened` → `ConfigStore.prefetchDriveGeometry()` (`ConfigStore.swift:93-97`) — три `Task`, каждый со своим `GET /config` (`:31-41`, декодирует весь `CarConfig`, берёт один домен); транспорт сериализует по пути (`CarTransport.swift:387-395`), `video` идёт третьим; `DriveView.swift:48` сеет раскладку из кэша при создании.
- **Вердикт.** ✓ форма и содержимое. ✗ разогрев: три последовательных чтения одного документа, `video` — последним, `ramp`/`trim`/`recovery` выбрасываются — `AJM-115` (low, Improvement).

### 2. Экран домена — читать прежде, чем показывать
- **Ожидание.** `app/settings` → «Читать прежде, чем показывать; непрочитанное — не число»: без чтения — «Не прочитано» + «Прочитать снова», ни одного числа; прочитанный домен не перечитывается; повторное нажатие не порождает второго запроса.
- **Код.** `ConfigDomainStore.loadIfNeeded` (`ConfigStore.swift:19-22`), `reload` с защёлкой `loading` (`:24-29`); `ConfigState.value` — `nil` для `.unknown`/`.failed` (`ConfigState.swift:38-43`). Экраны: `store.value != nil ? органы : ConfigNotice` — `WheelParamsView.swift:35-44`, `CarDimensionsView.swift:27-35`, `RampView.swift:36-54`, `RecoverView.swift:37-66`, `TrimView.swift:38-55`, `VideoSettingsView.swift:33-51`; «Домена нет в документе» → `.malformed` (`ConfigStore.swift:34`). Но все шесть держат `@State` с умолчаниями приложения и подставляют значение машинки в `.task { loadIfNeeded(); adopt() }` — после первого прохода тела.
- **Вердикт.** ✓ правило; ✗ первый кадр прочитанного домена собирается из умолчаний, а не из кэша — часть `AJM-106` (low).

### 3. Запись с экрана
- **Ожидание.** `app/settings` → «Один домен — один экран, запись — домен целиком и только он», «Писать только прочитанное и только изменённое», «Ползунки пишут на отпускание, остальные — на каждое изменение», «Редуктор — текст, проверенный до отправки», «Ответ машинки — правда».
- **Код.** `ConfigState.afterSaveRequest` (`ConfigState.swift:58-62`): нет прочитанного → отказ; равно прочитанному → отказ; иначе `.saving`. `write` (`ConfigStore.swift:62-73`): `POST` с `T.wrap(v)` — один домен, без `proto`; кэшу — домен из ответа, `?? v`. Ползунки — `onEditingChanged` (`RampView.swift:37-45`, `TrimView.swift:39-46`, `RecoverView.swift:49-53`, `VideoSettingsView.swift:34-42`, `enabled` берётся из `store.value`); степперы/переключатель/пикер — `.onChange` (`WheelParamsView.swift:100-143`, `RecoverView.swift:38-41`), «−»/«+» колеи — в обработчике кнопки (`CarDimensionsView.swift:102-106`). Редуктор: `commitGear` на каждый символ (`WheelParamsView.swift:132-135`, `:157-163`): запятая → точка, вне 1..300 — не шлём, округление `(g*100).rounded()` — половина от нуля, как `lround` машинки. Две записи одного домена подряд: транспорт сериализует по пути, `.saving(v1)` → `afterSaveRequest(v2)` → второй `POST` после первого — порядок ответов совпадает с порядком запросов, кэш кончает на правде машинки.
- **Вердикт.** ✓ форма записи, дедуп, порядок. ✗ `.onChange` не отличает подстановку `adopt()` от пользователя: `RecoverView` при `enabled:false` и `window_ms`, не кратном секунде, шлёт `POST` при открытии — `AJM-106` (low). ✗ редуктор: «12.5» — три записи (1.0, 12.0, 12.5) — `AJM-112` (low, Improvement; спека описывает код, расхождение со здравым смыслом).

### 4. Проверка тела на машинке
- **Ожидание.** `car/config` → «Тело записи — один объект JSON с доменами», «Любое подмножество доменов, каждый — целиком», «Всё тело проверяется до применения чего-либо», «Типы строгие», «Диапазон — отказ, не подрезка», «Десятичные поля округляются, потом проверяются». `car/status-and-version` → «Конверт ошибок», «Тело читается целиком».
- **Код.** `cfg_post` (`cfg_api.c:194-228`): тело до 512 байт через `api_read_body` (`api_util.c:49-61`, цикл до `Content-Length`); не JSON / не объект → `bad_json` без `field`; ключ не домен (в т. ч. `proto`) → `unknown_field`; пустой объект → `missing_field`; `parse_domain` (`:145-192`): не объект → `wrong_type` с ключом домена, лишнее поле → `unknown_field`, пропущенное → `missing_field`, `bool` только булево, `int`/`enum` только целое без дроби (`cfg_value.h:17-28`), `fixed` — округление половиной от нуля, потом диапазон (`:31-38`), `enum` вне списка → `not_allowed`. Первая ошибка — единственная в ответе; проход один по всем присутствующим доменам до применения.
- **Вердикт.** ✓. Домен дважды в одном теле — побеждает последний (cJSON держит оба); не описано и не вредно.

### 5. Применить → сохранить → ответить
- **Ожидание.** `car/config` → «Принято — значит применено и сохранено, до ответа»: домен пишется целиком одной записью, домены независимы, повтор того же не расходует флеш; потребитель видит сразу — `car/drive` (trim со следующей команды), `car/actuator-arbiter` (ramp со следующего такта), `car/recovery` (со следующей потери связи).
- **Код.** `cfg_api.c:233-250`: по доменам `set` → `save`; `cfg_json_save` (`cfg_json.c:9-24`) сравнивает с хранимым и пропускает `nvs_commit` при совпадении. Потребители: `car_drive` читает trim атомарно (`car.c:72`), писатель читает `ramp_get_ms()` каждый такт (`link.c:196`), `recovery_on_link_lost`/`snapshot_consume` берут `enabled`/`window_ms` в момент срабатывания (`recovery.c:165-176`, `:79-94`), `video_cfg_set` под замком (`video_cfg.c:45-53`). `wheel_set`/`dims_set` (`wheel.c:18-24`, `dims.c:16-20`) подрезают — но проверка уже отсекла всё вне диапазона, подрезка не срабатывает. Читатели `wheel`/`dims` — только httpd (тот же таск).
- **Вердикт.** ✓.

### 6. Отказ применить или сохранить
- **Ожидание.** `car/config` → «Отказ применить или сохранить — честный»: `500 write_failed`, `field` — ключ домена; отказавший домен возвращён к прежним значениям; домены раньше него остаются применёнными. `app/settings` → «Ответ машинки — правда, отказ записи — „не прочитано“»: любой отказ → «Не прочитано», «Прочитать снова» перечитывает и отбрасывает правку.
- **Код.** `cfg_api.c:237-248`: `prev` снимается до `set`; `set` вернул `false` (`ramp_set_ms`/`video_cfg_set` — замок) → `500` без применения; `save` ≠ `ESP_OK` → `set(prev)` → `500`; при провале и отката — только `ESP_LOGE` (`:243-246`, двойной отказ, не воспроизводится). Пульт: `afterSave(.failure)` → `.failed` (`ConfigState.swift:65-70`), `value == nil` → органы исчезают, `ConfigNotice` → `reload(); adopt()`.
- **Вердикт.** ✓. Ни хост, ни стенд не умеют вызвать отказ NVS — путь `500` живёт только чтением кода; отмечено в «Мок».

### 7. Старт машинки
- **Ожидание.** `car/config` → «При старте — из памяти, иначе умолчания контракта»: домен без записи или с неразбираемой — умолчания; значение вне диапазона — не как есть; **поле, которого в записи нет, — умолчание контракта** («Запись старше поля»). `car/recovery` → «Домен `recovery`»: то же по полям.
- **Код.** `ramp_init` (`ramp.c:44-59`): одно поле, диапазон 0..2000. `car_init` trim (`car.c:136-142`): одно поле, −30..30. `recovery_init` (`recovery.c:187-197`): `enabled` и `window_ms` независимо, диапазон. `video_cfg_init` (`video_cfg.c:69-85`): `bitrate_kbps` в диапазоне, `enabled` отдельно («absent: the default»). `wheel_init` (`wheel.c:38-60`): запись применяется только при всех четырёх полях, иначе целиком умолчания; вне `uint16` — отброс, внутри — подрезка `wheel_set` (внутри диапазона контракта — требование выполнено). `dims_init` (`dims.c:34-48`): то же для двух полей.
- **Вердикт.** ✓ для `ramp`, `trim`, `recovery`, `video`. ✗ `wheel`/`chassis`: запись без одного поля сбрасывает все — `AJM-104` (low). Латентно: сегодня новых полей нет.

### 8. Перезагрузка машинки при живом пульте
- **Ожидание.** `car/config` → «Пережить перезагрузку»: `GET` после перезагрузки — принятые значения. `app/drive-session` → «Тишина рвёт сессию»: пульт теряет сессию по тишине и открывает новую сам. `app/settings` → «Кэш доменов»: переоткрытие сессии кэш не сбрасывает; «Изменено мимо приложения» — прежнее значение до «Прочитать снова» или перезапуска.
- **Код.** Машинка отвечает только после `nvs_commit` (шаг 5), так что принятое переживает любую перезагрузку после ответа. Пульт: `.sessionClosed` чистит телеметрию, не кэш (`CarLink.swift:197-202`); `.sessionOpened` → `prefetchDriveGeometry` → `loadIfNeeded` — прочитанное не перечитывается. У прочитанного домена кнопки «Прочитать снова» нет (она в `ConfigNotice`, а тот только при `value == nil`): перечитать можно только отказом записи или перезапуском.
- **Вердикт.** ✓ при целой NVS — кэш и машинка совпадают, потому что каждая запись подтверждена. «Как долго пульт может показывать не то» — до перезапуска приложения; см. шаг 9.

### 9. Стирание NVS при смене формата
- **Ожидание.** `car/config` → «Формат памяти сменился»: умолчания и `storage.reset_at_boot: true`; `car/calibration` → «не смену формата хранилища»: `reset_at_boot:true`, `calibrated:false` — «пульту есть что сказать вместо молчаливой езды». `car/status-and-version` → «`storage.reset_at_boot`»: «единственный сигнал, по которому клиент может сказать об этом пользователю». Замысел `2026-08-23-ota-fix-decisions.md:97-99`: «the app shows a notice that calibration was lost». Обещание `protocol.md:509-511`: «a client should say so».
- **Код.** Машинка: `main.c:196-204` стирает и зовёт `status_api_note_nvs_wiped()`; `status_api.c:126-129` печатает флаг; `car_init` грузится некалиброванной (`car.c:129-134`). Пульт: единственный `GET /status` сессии — `fetchRadio` (`CarLink.swift:254-257`) — декодирует `CarStatus` и берёт только `radio`; `storage` не читает никто (`grep reset_at_boot app/` — только `Generated/CarAPI.swift`). Кэш живёт (шаг 8), обязательный мастер откроется по `calibrated:false` (шаг 11), но его шаги 1–2 покажут прежние `chassis`/`wheel` из кэша поверх машинки с умолчаниями; «Разгон», «Прямолинейность», «Авто-возврат», «Видео» — прежние значения, машинка едет на умолчаниях.
- **Вердикт.** ✗ `AJM-99` (medium): пульт не читает флаг, кэш не сбрасывается, уведомления нет. ? стенд: реальная смена версии NVS — флаг `true`, `GET /config` — умолчания, `calibrated:false` (см. «Стенд»).

### 10. Таблица калибровки и раскладка по умолчанию
- **Ожидание.** `car/calibration` → «Таблица говорит именами углов», «Калибровка — не условие движения», «`inverted` компенсирует прошивка». `car/drive` → «Борта раскладываются по углам», «Без калибровки — привод по умолчанию». `car/status-and-version` → `motors.calibrated` только при действительной таблице.
- **Код.** `calib_table_json` (`calib_wire.h:40-61`): `calibrated` + четыре записи в порядке `POS_FL..POS_RR` = `calibration.corners` контракта (`contract/car-api.json` → `calibration.corners`), пустой массив у некалиброванной; `inverted` = `sign < 0`. Умолчание — `car.c:20-30` (пары 0..3 по углам, знак +1, `deadzone` 0.05); `motors_plan` (`motors.c:15-44`): сторона × `sign`, пара `k` → каналы `2k`/`2k+1`, ровно один ненулевой. `calibrated` в телеметрии и `/status` — `calibration_is_valid()` из RAM (`telemetry.c:133`, `calibration.c:11-14`). Пульт собирает тело в том же порядке (`ControlModel.swift:74-79`, `CalibCorner.all`).
- **Вердикт.** ✓.

### 11. Мастер по требованию
- **Ожидание.** Дельта `ajm-64-known-fixes/specs/app/calibration` → «Два входа»: первый кадр `false` или смена `true→false` на открытом экране → обязательный мастер из трёх экранов; без «назад», без жеста, настройки недоступны; закрывается по `calibrated:true` или принятому сохранению; 2 с после — не переоткрывается; новая сессия судит по своему первому кадру.
- **Код.** `CalibGate.frame` (`CalibGate.swift:28-33`): `nil` — нет кадра; `true` — запомнить и не показывать; `false` внутри `grace` 2 с от последнего `true`/`saved` — не показывать; иначе показывать. Спрашивается на каждом кадре с `initial: true` (`DriveView.swift:189-193`); `CalibGate` — `@State` экрана вождения, новая сессия → новый экран → без памяти (`:21`, `:49`). Лист `interactiveDismissDisabled` (`:204`), шестерёнка `.disabled(showCalib)` (`:109`), `SplitScreen(onBack: nil)` у шага 3 (`CalibrationView.swift:39`), у шагов 1–2 вместо «назад» — «шаг N из 3» (`CarDimensionsView.swift:56-58`, `WheelParamsView.swift:68-70`). Хост-тест `app/tests/calibgate`. `true→false` на открытом экране в коде недостижимо иначе как через перезагрузку (сессия рвётся раньше); два листа на одном экране (`showSettings` + `showCalib`) — та же недостижимость.
- **Вердикт.** ✓ (AJM-63 закрыт AJM-67; базовая спека `app/calibration` до синка описывает старое поведение — дельта известна, отдельного issue не нужно).

### 12. Мастер по желанию
- **Ожидание.** `app/calibration` → из настроек, «назад» в любом состоянии; → «Шаг — это пара»: начинает с пустой таблицы, сохранённую не запрашивает.
- **Код.** `SettingsView.swift:30-36` толкает `CalibrationView(palette:)` — `dismissible` по умолчанию `true` → `onBack: { dismiss() }` (`CalibrationView.swift:39`) без условий на состояние; `@State` всё пустое при создании (`:10-20`); `client.fetch()` (`CalibClient.swift:11-13`) никто не зовёт.
- **Вердикт.** ✓. `protocol.md:593-594` («the wizard can show what is stored before overwriting it») — возможность, которой пульт не пользуется; не расхождение.

### 13. Шаг мастера — импульс, колесо, направление
- **Ожидание.** `app/calibration` → «Шаг — это пара, и крутится она вперёд», «Колесо называют только после состоявшегося импульса», «Несостоявшийся импульс — не шаг», «Направление задаёт знак», «Каждое колесо — один раз». `car/calibration` → «Импульс опознания минует таблицу», «Ответ на импульс — после импульса», «Запрос на импульс проверяется целиком». `car/drive` → «Импульс идентификации идёт мимо таблицы».
- **Код.** Пульт: `spin()` (`CalibrationView.swift:190-201`) шлёт `{pair: step, direction: forward}` (`CalibClient.swift:17-20`), `spinning` закрывает «Крутить» и колёса, только `200` даёт `spinOK`; любой `throw` → `spinFailed` → «Повторить» с тем же `step`; колесо `.disabled(assign[c] != nil || !spinOK || state != .spin)` (`:123`); `assign` (`:203-209`) — пара `step`, знак из ответа, `step += 1`, `spinOK = false`; экран направления без отмены (`:141-148`). Машинка: `calib_spin` (`calib_api.c:36-88`) — порядок отказов `unknown_field` → `missing_field` → `wrong_type` → `out_of_range` → `not_allowed`, `bad_json` без `field`; `car_spin_pair` (`car.c:118-125`) — канал `2k` или `2k+1`, 1600, захват `CALIB` на 600 мс без залипания; `vTaskDelay(600)` → `link_release_must` → `200` (`:85-87`); захват истекает сам (`link.c:161-165`), клиент может исчезнуть. Тайм-аут `POST` в пульте 5 с (`CarTransport.swift:378-385`) против 0,6 с. Разгон применяется и к импульсу: при `rise_ms` 2000 канал за 600 мс доходит до 1200, не до 1600 (`ramp.h:15-19`, `link.c:196-199`).
- **Вердикт.** ✓ протокол шага; ✗ два бюджета (600 мс удержания против 0..2000 мс разгона) не согласованы — `AJM-109` (low, Improvement); ? стенд: видно ли колесо при `rise_ms` 2000.

### 14. Импульс во время езды
- **Ожидание.** `car/calibration` → «Импульс подчиняется арбитру»: перебивает `remote`, команды пульта на время импульса отклоняются, но кормят сторожевой таймер, `link.timeouts` не растёт; `car/recovery` → отвергнутые команды не крошки; `app/calibration` → «Мастер живёт рядом с сессией»: поток не прерывается, `motors.owner: "calibration"` в телеметрии.
- **Код.** `LINK_SRC_CALIB > LINK_SRC_RT` (`link.h:26-34`), `link_arb_grant` (`:55-66`) отказывает младшему, пока захват не истёк. `on_command` (`rt_link.c:156-165`): `rt_session_command` до `car_drive` — таймер кормится и отвергнутой; крошка только при `true`. Пульт продолжает слать (стик закрыт листом — нули; геймпад — команду), `DriveView` показывает владельца `calibration` (`:413-415`). По истечении 600 мс цель — ноль, следующий кадр `remote` берёт захват заново и разгоняется с нуля. Крошки до импульса остаются; сегмент через «дыру» импульса ограничен `RECOVER_SEG_MAX_MS` — возврат приблизителен на 250 мс, как и задумано.
- **Вердикт.** ✓.

### 15. Импульс во время возврата
- **Ожидание.** `car/calibration` → «Импульс во время возврата»: возврат прерывается, `owner` — `calibration`; `car/recovery` → «Импульс мастера»: возврат окончен, после импульса машинка стоит.
- **Код.** `car_spin_pair` берёт захват над `RECOVER` (`link.h:26-34`), цель заменена импульсом сразу; следующий шаг `car_drive(LINK_SRC_RECOVER)` отвергнут → `aborted` (`recovery.c:137-141`) → `link_release_must(RECOVER)` — не трогает чужой захват (`link.c:87-96`); оставшиеся шаги не исполняются. По истечении импульса — ноль.
- **Вердикт.** ✓.

### 16. Импульс при `update`/`safe_stop` и при `motors.bus: down`
- **Ожидание.** `car/calibration` → `409 busy` без `field`, ни один канал не тронут, клиент мастер не продвигает; `app/calibration` → «Актуатор занят»: «Машинка не ответила», «Повторить». `car/status-and-version` → `bus: down` — машинка «неподвижна»; `app/calibration` → колесо только после состоявшегося импульса.
- **Код.** `car_spin_pair` → `link_set` → `false` при `OTA`/`SAFE` → `409 busy` (`calib_api.c:77-81`); пульт — `throw` → `spinFailed` (`CalibrationView.swift:196-198`). `SAFE` после прощания снимается принятием следующего пульта — мастер при живой сессии в него не упирается. Шина: `link_set` не смотрит на `link_bus_ok()`, писатель при `!pca9685_ready()` записи пропускает (`link.c:181-194`), через 600 мс — `200 ok`; мастер телеметрии не видит, предупреждение о шине — на экране вождения под листом (`DriveView.swift:405-409`); у обязательного мастера ни «назад», ни жеста, ни настроек.
- **Вердикт.** ✓ для `update`/`safe_stop`. ✗ шина `down`: «состоявшийся» импульс без движения → угадывание или тупик — `AJM-100` (medium). Пересечение с J6/J1 отмечено в issue.

### 17. Сохранение таблицы
- **Ожидание.** `app/calibration` → «Сохранение — вся таблица одним запросом», «Отказ сохранения — та же таблица ещё раз». `car/calibration` → «Сохранение — вся таблица или ничего», «Принятая таблица сохраняется, применяется и возвращается». `app/calibration` → по принятому сохранению мастер закрывается: из настроек — в настройки, обязательный — на экран вождения.
- **Код.** Пульт: «Сохранить» только при `step >= 4` (`CalibrationView.swift:32`, `:149-151`); `calibWheels` — четыре записи в порядке контракта (`ControlModel.swift:74-79`); `client.save` декодирует `Calibration` — `200` с нечитаемым телом = отказ (`CalibClient.swift:23-26`); отказ → `failed` → «Повторить» с тем же `assign` (`:154-156`, `:210-222`). Машинка: `calib_save` (`calib_api.c:91-173`) — порядок отказов по спеке, `where` = `wheels[i]`; `calibration_save` до `car_set_calibration` (`:159-170`), `ESP_ERR_INVALID_ARG` → `400 not_allowed wheels`, иное → `500 write_failed` без применения; ответ — `reply_table` из опубликованной таблицы; `calibration_set_valid(true)` → следующий кадр телеметрии `true`. Повтор той же таблицы — `cfg_json_save` не пишет флеш. Закрытие: `dismiss()` (`:216`) — в настройках pop к списку ✓; в обязательном мастере шаг 3 положен в `NavigationStack` листа через `NavigationLink` (`WheelParamsView.swift:83`, `DriveView.swift:195-204`) — `dismiss()` снимает шаг 3 на шаг 2, лист закрывает кадр `calibrated:true` через `CalibGate` (`:189-193`), `onDismiss → calib.saved()` (`:195-200`) срабатывает и в этом случае.
- **Вердикт.** ✓ протокол и проверка. ✗ обязательный мастер закрывается телеметрией, а не сохранением; мелькание шага 2 — `AJM-102` (low).

### 18. Уход и обрыв сессии
- **Ожидание.** `app/calibration` → «Уход с экрана ничего не сохраняет»: назначения отброшены, запрос в пути не отменяется, принятое машинкой остаётся принятым; → «Мастер живёт рядом с сессией»: обрыв сессии уносит экран вождения вместе с мастером, машинке ничего не послано. `car/calibration` → импульс заканчивается сам.
- **Код.** `@State` живёт с экземпляром `CalibrationView` — новый вход с нуля; `Task` в `spin()`/`save()` (`CalibrationView.swift:192`, `:212`) неструктурированные, уход их не отменяет, ответ ложится в мёртвое состояние; машинка отвечает на сохранение только после `nvs_commit`, так что «принято» = «сохранено». Обрыв: `LinkRule` уводит в «поиск», `DriveView` уходит из иерархии вместе с листом; `CarTransport.request` в пути завершится сам (тайм-аут или ответ). Телеметрия новой сессии несёт `calibrated:true`, если сохранение успело, — обязательный мастер не откроется (`CalibGate` новой сессии судит по первому кадру).
- **Вердикт.** ✓.

- Конфигурация живёт в памяти процесса (`tools/mock_car/state.py:242`): нет перезагрузки, нет NVS, нет отказа записи — шаги 5 (пропуск записи во флеш), 6 (`500 write_failed`, откат), 7 (старт из записи, запись старше поля) и 8 против мока не проверяются вовсе; conformance гоняет только проверку тела и `200` с полным документом.

- Мок стартует некалиброванным при каждом запуске и таблицу не хранит — удобно для мастера, но «перезагрузка после сохранения» (шаг 10) не имитируется.

- Спека `app/calibration` в базовой линии описывает мастер до AJM-67; мок этого не касается.
