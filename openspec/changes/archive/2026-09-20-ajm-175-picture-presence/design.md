# Design

## Context

`VideoLink` (`app/AJMiddleCar/VideoLink.swift`): приём и сборка на `queue`, счётчики публикуются на главный актор из `publishStats()` по `statsTimer` раз в секунду — там же считается `hasPicture = now − state.lastFrameAt < 2`. Первый собранный кадр (`receiveLoop`, ветка `.frame`) пишет `lastFrameAt` и отдаёт кадр слою через `onFrame` сразу, но `hasPicture` дождётся ближайшего тика — до 1 с картинки под плашкой. Строка причины в `DriveView.noPicture` берётся из телеметрии 5 Гц и переключается раньше. Отсюда лестница из AJM-175. `close()` сбрасывает `hasPicture`; `socketFailed` уже пользуется проверкой `conn === c`, чтобы отличить живой сокет от закрытого.

## Goals / Non-Goals

**Goals:** плашка уходит с первым кадром; порог свежести — чистая арифметика с хост-тестом; кадр от закрытого сокета флаг не поднимает.

**Non-Goals:** строка причины и телеметрия — не меняются; `fps`/`lostLast10s` остаются секундными; протокол, машинка, мок — не трогаются.

## Decisions

### 1. `PicturePresence` — чистая структура, а не ещё один таймер
`struct PicturePresence` (`app/AJMiddleCar/PicturePresence.swift`): `static let staleAfter: TimeInterval = 2`; `private(set) var lastFrameAt: Date`; `mutating func frame(at:) -> Bool` — возвращает `true`, если картинка *появилась* (до этого её не было по `present(at: t)`); `func present(at:) -> Bool` — был кадр меньше `staleAfter` назад; `mutating func reset()`. Заменяет `state.lastFrameAt` и число `2` в `publishStats`. Хост-тест `app/tests/picturepresence/main.swift` по образцу `videohold`: пусто → нет; кадр → есть и `frame` вернул `true`; второй кадр через 0,5 с → `frame` вернул `false` (не переход); тишина 2 с → нет; кадр после тишины → снова переход; `reset` → нет.
*Альтернатива:* дёргать `hasPicture` на каждом кадре — 20–30 публикаций в секунду на главный актор ради флага, который меняется два раза за сессию; хоп только на переходе — ноль лишней работы.

### 2. Переход поднимается из `receiveLoop` через главный актор, с проверкой сокета
В ветке `.frame`: `if state.presence.frame(at: now) { Task { @MainActor in guard self.conn === c else { return }; self.hasPicture = true } }` — тот же приём, что у `socketFailed`: кадр прежнего сокета, доставленный после `close()`, не оживит флаг, который `close()` только что сбросил. `publishStats` продолжает выставлять `hasPicture = state.presence.present(at: now)` — это и есть обратный переход «стало несвежим», через тик, как раньше; вперёд он теперь не опаздывает, а лишь подтверждает.
`state.lastFrameAt` уходит внутрь `PicturePresence`; `State.reset()` зовёт `presence.reset()`.

### 3. Плашка в `DriveView` не меняется
`if !video.hasPicture { noPicture }` и строка причины по `telemetry?.video.state` остаются: «Нет картинки» без причины при `streaming` — законное состояние настоящего простоя (машинка думает, что шлёт, кадров нет). Промежуточный шаг из AJM-175 исчезает потому, что плашка уходит с кадром, а не потому, что причину прячут.

## Risks / Trade-offs

- [Телеметрия сказала `streaming` раньше первого кадра] → на десятки миллисекунд плашка без причины возможна и после починки; это уже не «поверх идущей картинки», и спека этого не запрещает.
- [`Task { @MainActor }` на переходе — дополнительный хоп на пути кадра] → один раз за появление картинки, не на каждый кадр; слой получает кадр до хопа, как и сейчас.
- [Проверить вживую можно только симулятором] → PM снимает включение видео против мока после слияния; хост-тест закрывает арифметику, `xcodebuild` — сборку.
