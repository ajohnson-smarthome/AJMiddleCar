# Design

## Context

Мотивация — `proposal.md`; находки с `file:line` — issues `AJM-103…121`, `86`; трасса — `changes/archive/2026-09-19-ajm-64-logic-review/review/08-mock-blind-spots.md` с таблицей «требование → мок → conformance → вердикт» по каждой спеке `car/*`. Прошивка — правда; мок догоняет её, как уже сделали `AJM-71` и `AJM-89`.

Все файлы — `tools/`. Пересечения: `state.py` и `mock_car.py` нужны трём пунктам — они идут последовательно (1.1 → 1.2 → 1.4); три прогона и генератор независимы.

## Goals / Non-Goals

**Goals:**
- Мок, против которого зелёный conformance означает зелёный conformance против машинки — по всем требованиям `car/*`, которые видны по REST/UDP.
- Деградации железа воспроизводимы в симуляторе флагом.

**Non-Goals:**
- Не эмулировать физику (крутящий момент, шину I2C): деградация — состояние и его следствия на проводе, не причина.
- Не трогать контракт и прошивку; `AJM-113` — лимиты зеркалятся руками с комментарием, вынос в контракт — отдельный change.
- Не делать мок адаптера.

## Decisions

**Перезагрузка мока — тишина на всех портах (`AJM-103`).** На `REBOOT_QUIET_S` HTTP-сервер мока не принимает соединения (закрывает listener или отвечает `ConnectionResetError` до заголовков) — так пульт проходит путь `sawOffline → та же версия` и детектор отката становится проверяемым. Окно — то же, что у UDP; отдельного «длинного» окна нет: длительность — флаг `--reboot-s`, по умолчанию как сейчас.

**`/ota` — заголовок целиком (`AJM-105`).** Байт 0 (`0xE9`), `chip_id` из заголовка (ESP32-P4 — `18`, читается из константы мока с комментарием на `esp_image_format.h`) и магическое слово дескриптора приложения; чужой `chip_id` → `400 not_firmware` **после** чтения тела — как у машинки в `esp_ota_end`.

**Флаги деградации — состояние, не имитация причины (`AJM-116`).** Каждый флаг — поле состояния мока, которое читают уже существующие места: `motors.bus` в телеметрии и `/status`, `spin`, крошки; `video.state` и подписка; `radio`; `storage` и домены; одна запись → `500`. Все выключены по умолчанию; `test-all` запускает мок без них, и отдельный тест на каждый флаг.

**Валидатор — в эмиттере, не в моке (`AJM-111`).** `tools/gen_contract.py` порождает `generated.py`; исправляется шаблон: `math.isfinite` до арифметики → `wrong_type`, приведение к `int` для `int`/`enum` после проверки. Закрепляется в `tools/test_gen_contract.py`, чтобы регенерация не потеряла.

**Зеркала — тест, а не соглашение (`AJM-121`).** `tools/mock_car/test_mirrors.py` читает исходники прошивки (`recovery.c`, `link.h`, `calib_api.c`, `rt_link.h`) регулярными выражениями по образцу `test_ranges_match_the_firmware_today` и сверяет с константами мока и `SessionPolicy`/`stallTimeout` пульта; в `test-all.sh`.

**Клип 16:9 (`AJM-110`).** `ffmpeg testsrc2=size=1280x720`, те же кодек и длительность, ≤ 400 КБ; `test_video.py` разбирает SPS и закрепляет размеры против `VIDEO["width"]`/`["height"]`.

**Легенды прогонов — безопасные для машинки на подставке (`AJM-117/118/119`).** Каждая новая легенда — коротко и без езды: сторож — 0,5 с тишины после нулей; возврат — 1 с `throttle: 0.3` перед тишиной, ожидание `recovering` в первом кадре; простой — не проверяется (10 с ожидания, только `--slow`); видео — чужой sid/`hello` на видеопорту → тишина, `bye` → тишина в пределах такта, `/status.video` посреди потока, гистограмма интервалов чанков (медиана ≈ 3 мс); REST — перечисленные в issue тела. Все идут и против мока, и против машинки.

**Flaky (`AJM-86`).** `test-all.sh` перестаёт `rm -f "$LOG"` при ненулевом выходе conformance — лог остаётся с путём в выводе; пункт пытается воспроизвести циклом из 20 прогонов; воспроизвёлся — чинить (вероятно, старт видеопотока занимает event loop мока и HTTP не успевает принять), нет — `Canceled` с записью «20 прогонов, не воспроизвелось, лог теперь сохраняется».

## Risks / Trade-offs

- [Тишина REST в паузе перезагрузки сломает `tools/conformance.py`, если он бьёт в `/ota`] → прогон уже ждёт «перезагрузку» по `hello`; проверить, что шаг `/ota` прогона не ждёт REST раньше паузы; иначе — `--reboot-s 0` для прогона.
- [Флаг `--bus down` ломает `conformance.py`, ожидающий `200` на `spin`] → флаги выключены по умолчанию; тест на флаг — свой, не conformance.
- [Тест зеркал завязан на форму исходников прошивки] → регулярные выражения по имени константы, как уже сделано для диапазонов; сломается — сломается громко.
- [Новые легенды прогонов красные против машинки до слияния `review-fixes`] → легенды описывают поведение по спекам, которые прошивка уже выполняет (сторож, возврат, вытеснение); те, что зависят от починки (`spin` при `bus: down`), не добавляются.
