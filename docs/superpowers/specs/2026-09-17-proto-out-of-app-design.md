# `proto` вон из решений приложения — совместимость держится на выпуске

**Статус:** утверждён в чате 2026-09-17; план — `docs/superpowers/plans/2026-09-17-proto-out-of-app.md`.
**Опирается на:** `docs/superpowers/specs/2026-09-17-version-endpoint-design.md` (замороженный
`GET /version` с полем `proto`), `docs/superpowers/specs/2026-09-17-board-ladder-design.md`
(одна лестница, `VersionRule` — одно правило на обе платы),
`docs/superpowers/specs/2026-09-16-one-release-gate-design.md` (один выпуск за запуск: приложение
и обе прошивки собраны вместе).

## Зачем

Сейчас приложение при проверке платы опирается на **две** оси версии: `fw/build` (какой выпуск
прошит — сравнение с тегом релиза) и `proto` (какой контракт провода понимает бинарь — сравнение
с собственной константой приложения). Это неверно: `build` **субсумирует** `proto` — один и тот
же `proto` не гарантирует совместимость (другой билд при том же протоколе может быть несовместим),
а «билд платы совпадает с тегом релиза» — гарантирует, потому что один выпуск поставляет приложение
и обе прошивки вместе. Значит вторая ось на стороне приложения — лишняя, и её поддержка (ветка в
`VersionRule`, состояние `protoMismatch`/`wrongProto`, экран S32 «Приложение устарело») — мёртвый
груз: при одном владельце и совместной поставке расхождения по протоколу быть не может.

**Инвариант, который мы принимаем:** приложение всегда последней возможной версии ⟹ всегда требует
последний билд обеих плат; совместимость = «билд платы == тег релиза». Сегодня это верно **по
построению** — приложение собирается из исходников, оно всегда последнее. То, что мы при этом
отдаём, — защита «устаревшее приложение + новая прошивка»; её правильное место — **собственная
проверка версии приложения при старте (App Store)**, которой сейчас нет. Это фиксируется как
инвариант + TODO, не реализуется здесь (см. §5).

`proto` при этом **остаётся на проводе** как версия формата — это дешёвая (1 байт), спящая сегодня
страховка, которая делает изменение формата провода в будущем безопасным (старый бинарь по `proto`
отвергнет чужой формат, а не неверно распарсит). Мы её не трогаем; меняются только **решения
приложения**.

## 1. Что меняется — приложение перестаёт читать `proto` для любых решений

Приложение **продолжает писать** `proto` в исходящие датаграммы (`RTFrame.hello/drive/bye/view` —
иначе прошивка дропнет их своим proto-гейтом) и продолжает декодировать поле `proto` из `/version`
(оно во frozen-документе). Но перестаёт **сравнивать** входящий `proto` с собственной константой и
принимать по нему решения — на всех четырёх уровнях:

### 1.1 Гейт (`VersionRule`)
- `VersionRule.step` теряет параметр `appProto` и последнюю проверку `guard v.proto == appProto`.
  Новый порядок: `device → rolled_back → fw/build → ok`.
- `VersionStep.appBehind(proto:)` удаляется.

### 1.2 Лестница (`StageRule` / `AppFlow`)
- `Board.Identity` теряет поле `proto`; `StageRule.decide` перестаёт передавать `appProto`.
- `GateStep.appBehind(proto:)` удаляется.
- `AppFlow.dongleBoard`/`carBoard` перестают передавать `proto:` в `Board.Identity(...)`.
- `AppFlow.carIdentified` не затрагивается — оно и сейчас решает по `build` (`GateRule.mayDrive`).

### 1.3 Рантайм-сессия (`RTFrame` / `SessionPolicy` / `CarTransport` / `CarLink` / `LinkState`)
- `RTFrame.parse`: `hello_ack` разбирается в `.helloReply` **независимо** от входящего `proto`
  (проверка `guard theirs == CarContract.proto else return .protoMismatch` убирается); телеметрия
  разбирается независимо от `proto` (guard `theirs == CarContract.proto` убирается). Исходящие
  фреймы по-прежнему пишут `CarContract.proto`. `RTFrame.Inbound.protoMismatch` удаляется.
- `SessionPolicy.HandshakeOutcome.protoMismatch` удаляется; `handshakeOutcome` возвращает только
  `.identity`/`.ignore`.
- `CarTransport`: `Event.protoMismatch` и `Handshake.protoMismatch` удаляются; путь handshake
  больше не ветвится по протоколу; `throw CarError.malformed("protocol …")` убирается.
- `CarLink.handle`: ветка `case .protoMismatch` удаляется; `session` больше не принимает значение
  `.protoMismatch`.
- `LinkState`: `SessionState.protoMismatch` и `Link.wrongProto` удаляются; `survivingSessionEnd`
  упрощается (`case .foreign: return self`); `LinkRule.compose` теряет строку
  `if case .protoMismatch … return .wrongProto`.

### 1.4 Экраны (`AppFlow` фаза / `ConnectView` / `AJMiddleCarApp`)
- Экран **S32 «Приложение устарело»** удаляется целиком: ветки `.appBehind` в
  `ConnectView.stageScene/title/message/actionButton`; в `AJMiddleCarApp` страж
  `case .wrongProto` (у `Link` его больше нет) убирается из `.onChange(of: link.state)`.
- `CarLink` `retryAfterWrongCar` остаётся (его вторая роль — чужая машинка `.foreign`).

## 2. Что НЕ трогаем

- **Провод и контракт:** поле `proto` в `/version`, в `hello_ack`, в каждой rt- и видео-датаграмме,
  в конверте REST — остаётся. Контракт (`contract/*.json`), генераторы, обе прошивки, мок и
  конформанс **не меняются**.
- **Прошивочный proto-гейт:** прошивка по-прежнему дропает входящую датаграмму с чужим `proto` —
  это приёмная санитария на её стороне, независимая от решений приложения.
- **Константы `CarContract.proto` / `DongleContract.proto`** остаются — приложение пишет их в
  исходящие датаграммы. Убирается только их использование как **порога сравнения** на входе.
- **Поле `proto` в `DeviceVersion`** (Swift-структура `/version`) остаётся — документ декодируется
  целиком; поле просто больше нигде не читается.

## 3. Строки, галерея

- Строки `appBehind.title`, `appBehindSub.dongle`, `appBehindSub.car` удаляются (grep-подтверждённо:
  только эти три и их аксессоры `appBehindTitle`/`appBehindSub`).
- `wrongProto.*` уже удалены в лестнице плат; здесь удаляются их последние следы в коде
  (`Link.wrongProto`, `SessionState.protoMismatch`).
- `GalleryView`: кадры `("App behind (dongle)", …)` и `("App behind (car)", …)` удаляются.

## 4. Тесты

- `tests/versionrule`: убрать кейсы `.appBehind` (строки «current build, another proto», «ahead and
  another proto»); убрать параметр `appProto` из локального `step(...)`; правило теперь
  `device → rolled_back → fw/build → ok`.
- `tests/stagerule`: убрать кейс `.appBehind` («current but foreign proto»); `Board.Identity` без
  `proto`.
- `tests/sessionpolicy`: убрать кейсы `protoMismatch` (два: для нашего sid и для чужого); `ack(...)`
  больше не варьирует `proto` для этого.
- `tests/carlink`, `tests/rtframe`: убрать проверки `protoMismatch`/`wrongProto`; `RTFrame.parse`
  на `hello_ack` с любым `proto` даёт `.helloReply`, на телеметрии с любым `proto` — `.telemetry`.
- Остальные хост-тесты не затрагиваются; исходящие фреймы по-прежнему содержат `proto`, поэтому
  фикстуры, что его проверяют на выходе, не меняются.

## 6. Чего не делаем

- Не убираем `proto` с провода, из контракта, из прошивок, из мока и конформанса — это отдельная
  большая работа с высокой ценой и почти нулевой выгодой, и она убрала бы единственный дешёвый путь
  к безопасному изменению формата провода. Если `proto` когда-нибудь реально встанет поперёк —
  отдельная спека.
- Не реализуем самопроверку версии приложения при старте (нужен App Store) — только фиксируем как
  инвариант/TODO.
- Не трогаем `device`-идентичность (`wrongCar`/S23), откат (S31/S10), выпуск (S4–S6),
  принудительное обновление (S27/S11) — это ортогональные оси, они остаются.
